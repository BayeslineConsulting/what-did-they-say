# Theory Dictionary (open only at Step 5)

These constructs are a lens for naming what emerged, not a list of things to look for. For each category from second-cycle coding, scan this file and record the closest construct, its source, and a one-line justification — or `novel`. A category that maps to nothing is a candidate contribution; do not force a fit.

## A. Buyer-side constructs (what the prospect is expressing)

### UTAUT — Venkatesh, Thong & Xu (2016), synthesizing Venkatesh et al. (2003)
| Construct | Definition | Sounds like in a call |
|---|---|---|
| Performance expectancy | Degree to which using the offering will help the buyer attain gains in job performance | "would this actually cut our processing time," ROI questions, comparing to current results |
| Effort expectancy | Degree of ease associated with use | "how hard is onboarding," training burden, "my team isn't technical" |
| Social influence | Degree to which the buyer perceives that important others believe they should use it | "my CFO will ask," peer references, "who else in our industry uses this" |
| Facilitating conditions | Belief that organizational and technical infrastructure exists to support use | integration questions, "we'd need IT," support model, data migration |
| Hedonic motivation (UTAUT2) | Fun or pleasure from use | demo delight, "that's slick" |
| Price value (UTAUT2) | Cognitive trade-off between perceived benefits and monetary cost | price objections framed against benefit, not just cost |
| Habit (UTAUT2) | Extent to which behavior is automatic from prior use | "we've always done it this way," incumbent inertia |
| Moderators | Age, gender, experience, voluntariness | mention of mandates, tenure, prior tool experience |

### Theory of Trying — Bagozzi, Davis & Warshaw (1992)
Adoption of something that must be *learned* is a goal, not a simple act. Attitudes toward the goal have three components; early in the decision **fear of failure dominates** (nearly twice the weight of anticipated success), later attitudes toward success dominate.
| Construct | Definition | Sounds like in a call |
|---|---|---|
| Attitude toward success (AS) | Affect about the consequences of succeeding at adoption | "if this works we'd finally…" |
| Attitude toward failure (AF) | Affect about the consequences of trying and failing | "last time we switched systems it was a disaster," career-risk language |
| Attitude toward process (AP) | Affect about the effort of striving itself | "the migration alone…", implementation dread |
| Intention to try / trying | Volitional commitment to attempt, and effort expended | agreeing to a pilot, assigning an internal owner |

### Effective Use — Burton-Jones & Grange (working paper)
Use matters only if it is *effective*: increases the user's goal achievement.
| Construct | Definition | Sounds like in a call |
|---|---|---|
| Representational fidelity | Extent to which the system's representations faithfully reflect the domain the buyer needs | "does the dashboard reflect what's actually happening," data accuracy worries |
| Transparent interaction | Extent to which the user reaches the representations unimpeded by interface and hardware | UI friction, "how many clicks," device constraints |
| Adaptation actions | User actions to change the system or access to it | customization requests, "can we configure…" |
| Learning actions | User actions to learn the domain, the system, or the mapping between them | training asks, "who teaches my people" |

## B. Seller-side constructs (what the rep is doing)
Use these only if a rep-behavior category clearly maps; most rep process codes will be `novel` relative to this dictionary, and that is expected.
- **Reducing anticipated failure** (from Theory of Trying's policy implications: "training wheels," reversibility, undo) — reps offering pilots, phased rollouts, exit clauses, reference calls.
- **Raising facilitating conditions** (UTAUT) — reps proactively describing integration, support, and implementation resources before asked.
- **Enabling learning/adaptation actions** (Effective Use) — reps offering configuration, training plans, or domain education.

## C. Quality of theory use — Painter, Borba, Hynes, Mays & Glanz (2008)
Rate the run on this continuum and state it in the summary:
| Level | Criterion |
|---|---|
| Informed by theory | Constructs named but few operationalized |
| Applied theory | Between one and half of a theory's constructs are actually measured in the coding |
| Testing theory | More than half of constructs measured and compared across outcomes, or two theories compared |
| Building theory | Novel categories integrated with existing constructs into an extended framework |

Most single runs land at *applied*. Reaching *testing* requires enough calls to compare construct density across closed and lost outcomes for more than half of a theory's constructs; *building* requires the novel categories to be written up as extensions.
